# Project instructions — Campus Events prototype

Read PRD.md and ACCEPTANCE_CRITERIA.md before doing anything.

## What this is
A v1 prototype that recommends up to three fictional campus events to a student based on interests and availability. Three screens: preferences, recommendations, event details.

## Rules
- Plan before code. For any new feature, list the files you'll touch and wait for approval.
- One change per request. Do not refactor or restyle anything I didn't ask about.
- Scope is PRD.md "Build now." If I ask for something under "Build later," say so and stop.
- Fictional data only, in one static file. No logins, payments, or external APIs.
- Mobile-first. Test at 390px width.
- No secrets in the repo. Keep a .gitignore with .env in it.
- After every change: run the app, walk the relevant section of ACCEPTANCE_CRITERIA.md, and tell me which boxes pass and which don't.
- When something fails, explain the cause in plain English before proposing a fix.
- Update README.md whenever setup or run steps change.

## Stack
Keep it simple: a single-page web app with no backend. Whatever you choose, it must deploy to Railway as a static site or a one-process Node server.
